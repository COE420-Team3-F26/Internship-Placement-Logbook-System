**Software Process Model**



We chose the incremental model as the most appropriate software process model because it best matches the expected development of our system. The system can be divided into multiple manageable parts that can be developed and delivered progressively. User management, internship applications and placements, supervisor assignment, weekly logbook submission, progress tracking and notifications are the increments into which we can split our system. Using this approach, we can produce an early working software, test each part separately, and modify the increments later whenever requirements change, become more clear, or feedback from users is received. 

However, this model also has some drawbacks. The main ones include thoroughly breaking down the system into suitable increments, the possibility of having integration problems between independently developed parts, and the repeated testing whenever a new increment is added. 

There are different ways that help reduce these drawbacks. One of them is defining the general architecture and database structure of the system early on.  Another one is testing each increment before going on to the next one. Also, prioritizing the most important features and integrating components regularly will help us manage these issues.
